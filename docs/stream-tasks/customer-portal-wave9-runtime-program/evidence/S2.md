## Delivered Contract

- One normalized `care` module renders all eight accepted vertical hubs:
  `equipment`, `seasonLog`, `program`, `water`, `roof`, `monitoring`,
  `healthCare`, and `beautyCare`.
- Care components consume normalized props. Raw accepted fixtures are isolated
  in `runtime/data/care-fixtures.js`; their eight payloads deep-equal the
  accepted design source.
- The protected Care fixture is not statically imported. It is requested by an
  async-only adapter only after module, session, customer scope, tenant scope,
  entitlement, and fixture-mode preflight all grant access.
- Disabled, unauthenticated, missing-scope, not-entitled, forbidden, checking,
  preflight-error, and unopened-live decisions publish safe envelopes with
  `content: null`, no protected adapter call, and no protected fixture request.
- Runtime generations and single-flight loading prevent stale payloads after
  revoke, sign-out, retry, clear, or vertical switch. A real intended-route
  `/care -> auth.phone -> auth.code -> care` flow loads once after grant and
  reaches `ready`.
- All Care envelope shapes and vertical display metadata are owned by the
  dedicated Care normalizer. The module descriptor owns orchestration only.
- Health remains logistics and secure-document metadata only. No clinical
  values, diagnoses, outcomes, advice, or document contents were introduced.
- `care.selectUnit`, `care.selectSpecialist`, and `care.completeTask` produce
  inspectable local state. `care.requestRetreat` uses entity-keyed shared
  single-flight state and inspectable `submitting -> submitted` readback.
- `care.download`, `care.contactProvider`, and `care.openSecureDoc` are
  explicitly unavailable without approved URL, authorization, audit, and
  secure-view contracts. No toast or timeout is treated as success.
- Every Care command reauthorizes the current module/session/scopes/
  entitlement/vertical/action/entity immediately before mutation. Async
  completion additionally rechecks the authorization epoch and current entity.

## Audit History

### Cycle 1

The independent validator found that missing scope values failed open, adapter
call proof used mutable production counters, and the S1 Care fallback assertion
was stale. Remediation made both scopes strictly required, replaced production
instrumentation with test-owned spies, added missing-scope cases, and updated
the granted route expectation to `ready`.

### Cycle 2

The validator found pre-grant static fixture IO, commands trusting a stale
envelope, retreat races restoring protected IDs, global retreat status,
unsupported payload fallback success, split envelope ownership, and incomplete
security tests. Remediation added dynamic protected imports, async generation
invalidation, fail-closed command authorization, authorization epochs,
entity-scoped state, strict payload grammar, normalizer-owned envelopes, and
network/lifecycle/sink tests. The malformed transferred Care CSS comment was
also repaired.

### Cycle 3

The validator found stale unauthorized state after intended-route sign-in,
unhandled delegated Promise rejection, stale screenshot toast, and an undefined
error color token. Remediation added granted-transition async loading,
thenable-aware delegated dispatch, clean screenshot setup, and `--danger`.
Protected-ID derivation was expanded to 35 recursive `id`, case-insensitive
`*Id`, and scope values; generalized denied command errors now clear after a
successful payload or command.

Final result: **approved with no actionable findings.** The validator
independently reproduced auth resume and delegated rejection behavior and
confirmed the earlier security findings remained closed.
