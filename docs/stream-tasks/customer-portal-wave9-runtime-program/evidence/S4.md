## Exact Effect Accounting

Care controls made unavailable in S2 intentionally differ from the accepted
designer fixture, which presents them as active. S4 preserves the truthful S2
color, opacity, disabled, and `aria-disabled` treatment.

For each source-effect row the harness:

1. Records the computed border box, box-shadow string, action id, entity id,
   disabled truth, and selector for every runtime unavailable control.
2. Parses every outer box shadow into offset, blur, and spread. The visual
   kernel extent is derived as `ceil(1.5 * blur) + spread`; directional
   extensions include signed offsets and are clipped to the captured image.
   Inset shadows do not expand the envelope. There is no fixed padding or
   blanket rectangle.
3. Computes 8-connected components from every raw changed pixel.
4. Requires the complete bounding box of each component to be contained by at
   least one computed control envelope. Intersection alone is insufficient.
5. Independently requires an actual changed pixel in that same owning
   control's computed border box. Envelope-only containment is insufficient.
6. Persists border/shadow derivation, extension distances, envelope and
   component bounds, both booleans, and the combined control association.
7. Excludes only changed pixels satisfying both predicates and fails on any
   component without a valid owner.

Across 19 rows, all 182 components are envelope-contained and intersect their
owning control border box; zero are unassociated.
Raw metrics and `diff.webp` remain available; `component-diff.webp` represents
only the component-accounted comparison and is never called full-image zero.

The built-in adversarial self-tests reject a thin changed path extending one
pixel beyond an envelope, an adjacent unrelated patch, and an isolated patch
inside the shadow envelope but outside the owning border box. A contained
control effect with a changed border-box pixel is accepted.

## Deterministic Verification

`visual-acceptance.mjs --verify` is non-writing and always runs the complete
matrix. Persisted JSON contains no timestamp and stores normalized
path/query/hash URLs without random server ports.

Verification checks:

- aggregate schema, metrics, modes, component associations, and assertions;
- every per-row metrics JSON;
- SHA-256 of every persisted lossless reference, implementation, diff, and
  component-diff WebP;
- decoded RGBA dimensions and pixel SHA-256 for every persisted WebP;
- decoded persisted reference/implementation pixels against fresh PNG capture
  pixels;
- exact canonical equality with the stored packet;
- artifact-tree bytes and mtimes before and after verification.

Capture readiness now requires loaded fonts/images, stable app route/state and
DOM geometry across consecutive animation frames, a deterministic full-document
prepaint pass, normalized focus/hover state, and two authenticated captures from
separate synchronized Chrome processes. Each process uses a fresh ready page;
no screenshot retry or variance threshold is used. Per-row evidence persists
prepaint positions, frame counts, warm-up hashes, and equal authenticated
capture hashes.

Readiness and prepaint only inspect layout, scroll for paint coverage, move the
pointer, and clear focus. They do not call `AircovePortal.setState({})`, mutate
product state, or force a product rerender after the real setup/action flow.

Browser ownership is bounded to deterministic four-row batches. Each batch
owns exactly two direct Chrome PIDs and the next batch cannot start until both
browser transports close and every owned PID is absent. Timeout helpers clear
their timers. Graceful close errors/timeouts and final remaining PIDs fail the
run; TERM/KILL fallback is restricted to tracked owned PIDs. The HTTP server is
also closed and asserted non-listening. There is no `process.exit` or
`process.exitCode`; successful runs must leave the event loop naturally.

`--diagnostic-dir` is restricted to a child of the system temporary directory.
On persisted or capture mismatch it writes fresh/persisted/diff PNG/WebP files,
raw metrics, changed-component bounds, and component summaries there only.
Evidence is never used for diagnostics.

Three final full verifies ran strictly sequentially in fresh processes:

| run | delay | PID | exit | rows | process after wait |
| --- | ---: | ---: | ---: | ---: | --- |
| verify 1 | none | `97300` | 0 | 62/62 | absent |
| verify 2 | none, after verify 1 exit | `3623` | 0 | 62/62 | absent |
| verify 3 | 60 seconds after verify 2 exit | `10166` | 0 | 62/62 | absent |

All three runs matched canonical row/aggregate metrics and persisted decoded
pixels and left artifact bytes/mtimes unchanged. Isolated temporary-packet tests
also proved that verification fails for a missing WebP (`ENOENT`), corrupt WebP
(decoder rejection), and stale but valid WebP (decoded-pixel SHA mismatch).

Validation history is intentionally retained: an operator schema-v4 verify
first exposed `seo-ready-hvac-1440` nondeterminism. Cycle-4 fail-fast attempts
then exposed 32 paint-edge pixels in `care-ready-health-1180`, four rounded-icon
pixels in HVAC, and 126 action-state icon-corner pixels in FAQ/selected-service.
The accepted fix is state/layout/font readiness plus full-document prepaint and
independent dual-browser captures. Failed updates never wrote an aggregate and
were replaced by the complete schema-v5 packet. Two overlapping interrupted
verifies (`87665`, `93909`) were terminated and are not counted as proof.

Cycle 5 intentionally invalidated schema v5. Its first 62-row schema-v6 update
exposed the remaining lifecycle defect: both long-lived browsers timed out on
graceful close, so the harness reaped them, failed the run, and did not write an
aggregate. The accepted fix bounds ownership to four rows per browser pair.
A replacement schema-v6 update and one full fresh-process `--verify` both
completed 62/62 with exit `0`, canonical metrics/image hashes equal, read-only
tree proof intact, and no remaining harness or Chrome process. A separate
natural-exit smoke recorded PID `45188`, exit `0`, PID absent after shell
`wait`, and no direct Chrome child; no timeout wrapper or kill was used.
