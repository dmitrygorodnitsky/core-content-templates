## Delivered Contract

- The authenticated portal CMS block now exposes exactly eight verticals and
  themes, three profiles, the Care module, runtime-owned Care authorization,
  and the existing auth, router, data, error, and PIM controls. Customer scope,
  entitlements, permissions, and sensitive Care data are not CMS defaults.
- `portal_default_mode` is explicitly initial-default-only. Auth mode is emitted
  through `data-portal-auth-mode`; empty module override delegates to the
  selected runtime profile rather than freezing one CMS module list.
- Public SEO has an independent CMS block, Draft 2020-12 input schema, root
  template, progressive-enhancement entry, and stylesheet inventory. Strict
  production generation requires a complete `public-authored` payload and
  emits useful title, description, canonical, H1, body, native FAQ, and FAQ
  JSON-LD before JavaScript.
- The committed public preview uses the explicit `public-authored-test`
  classification, a visible test notice, and `noindex,nofollow`. Production
  `public-authored` output remains indexable.
- Portal and public SEO package independently into five deterministic files.
  Export is transactional: all files are prepared and hashed in a confined
  sibling staging directory before promotion; invalid input preserves the
  previous export byte-for-byte and leaves no staging or backup debris.
- No CMS upload was performed.

## Audit History

- Cycle 1 found missing production schema enforcement, indexable test output,
  and unvalidated portal overrides. The generator now validates before
  normalization, test output is noindex, and overrides fail closed.
- Cycle 2 found ignored `$ref`/`oneOf` siblings and destructive partial export
  on invalid SEO input. Sibling assertions now compose and export is
  transactional with rollback evidence.
- Cycle 3 found non-structural JSON equality. `uniqueItems`, `const`, and
  `enum` now share structural JSON equality with adversarial coverage.
- Cycle 4 found accepted but unexecuted schema forms. The supported schema
  subset now meta-validates every keyword value and rejects unsupported
  boolean/subschema forms.
- Cycle 5 found permissive `$ref` targets and UTF-16 `minLength`. References
  now resolve only through own JSON Pointer properties into scanned schema
  nodes, and string length uses Unicode code points.
- Cycle 6 independently returned **APPROVED** with no actionable findings.

## Honest Residuals

- No external Draft 2020-12 validator is installed in the bundled or system
  runtime. The production generator therefore uses a code-owned, fail-closed
  subset validator limited to the keywords used by the committed schema. Its
  keyword forms, composition, references, JSON equality, and Unicode length
  semantics have direct adversarial coverage; unsupported forms are rejected.
- The committed public preview is test content, not production CMS truth.
  Production export requires a real complete authored payload.
- `care.live` and sensitive Health live actions remain `not_opened` under the
  S5 contract. CMS packaging did not create endpoint behavior.
