## Frozen Architecture Decisions

1. `c9879ae` is authoritative for visual composition, responsive behavior,
   stable ids/hooks, and accepted visual states. `ARCHITECTURE.md` is
   authoritative for production business/security/data/CMS/delivery contracts;
   design demo timers and mock transitions are not business authority.
2. Production remains no-build native ES modules: no React, bundler, or package
   manager.
3. There are exactly 17 accepted parity routes, eight configured themes, and
   three configured profiles.
4. Care is one normalized, entitlement-aware tagged module with eight possible
   kind-specific payloads; route logic does not own vertical shape logic.
5. Care uses authorization-before-load. Disabled, unauthenticated,
   not-entitled, forbidden, and pre-payload loading/error states have
   `content: null`, do not require `kind`, and never call or leak data from the
   protected adapter.
6. `module.normalize` delegates to a dedicated normalizer.
7. `seo.landing` is a parity route; production SEO is a separate public,
   indexable CMS document with server-visible metadata/content/canonical/FAQ
   structured data and no portal auth/shell/hash dependency.
8. CMS owns SEO metadata/content slots. Nullable/regulated/business facts are
   omitted or honest, never invented.
9. Health shows logistics and secure-document metadata only, never clinical
   metrics/results/claims. Sensitive Health/Beauty live paths require auth,
   customer/tenant object scope, RBAC/ABAC, consent/purpose, audit, least-data
   normalization, and secure document delivery before activation.
10. HTML light/dark `data-mode` is initial-default-only; user choice survives
    hydration and rerender. `portal_data_mode` is a separate fixture/live axis.
11. No dev-only compatibility aliases, preview toolbar dependency, silent
    live-to-fixture fallback, or fallback/mock mutation success may ship.
12. Pricing/products PIM and all existing stormOps behavior are mandatory
    regression baselines.
13. The authenticated CMS root preserves the exact current config/auth/data/PIM
    attribute contract and owns shell/config only; route-specific content stays
    in route/module owners.
14. `data-requires-confirmation` is a stable production hook: marked commands
    require explicit confirmation before dispatch and still validate business
    authorization/entity state in the handler.
15. The accepted SEO inventory contains 14 component ids, including the
    reusable `seo-service-card`; `seo-meta-preview` remains parity-only and is
    excluded from production UI.
16. Order, Proposal, and PricingProduct canonical shapes remain production
    targets, while current raw-ish order/site containers and direct `F.*`
    consumption are explicit baseline gaps. Migration requires coordinated
    normalizer, consumer, fixture/PIM, and browser changes without a dev-only
    compatibility layer.
17. Functional S7 coverage is exhaustive across every route/profile and every
    applicable fallback, disabled access, permission denial, pending mutation,
    and failed mutation; representative state smoke cannot close the gate.
18. Stale manifest prose counts do not mutate the accepted source or override
    actual files/current HANDOFF/current manifest arrays/fixtures/scenarios for
    inventory reconciliation.
