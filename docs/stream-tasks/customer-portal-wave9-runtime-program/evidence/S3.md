## Delivered Contract

- Accepted SEO sections, ordering, styles, hooks, and all eight vertical fixture
  sets are available through reusable normalized runtime components.
- The authenticated portal keeps `seo.landing` only as an executable parity
  route. Production SEO is a separate public document with no portal auth,
  AppShell, or hash-router dependency.
- Public generation requires an explicit complete CMS-authored payload and an
  explicit output path. It has no default fixture, reference-content fallback,
  or synthetic success API.
- Title, description, canonical URL, authored brand, one H1, visible FAQ
  content, and matching FAQ JSON-LD are emitted in raw HTML before JavaScript.
- Canonical and destination URL policy fails closed on HTTP, credentials,
  fragments, unapproved origins, reserved/local/test/example hosts, IP
  literals, and non-public DNS names. Explicit reference/test normalization is
  separately classified and may use allowlisted `.test` origins.
- FAQ uses native `details`/`summary`, so disclosure remains usable without
  JavaScript. Service actions are authored links or disabled before
  interaction; CTA targets are real URLs, telephone links, or local anchors.
- Hero offer, trust, pricing, service area, reviews, and FAQ independently
  suppress ready content in `loading` and `empty` states and render explicit
  state treatment.
- The checked designer-fixture preview is visibly `reference-only`, carries
  `noindex,nofollow`, and is not an accepted production content source.

## Audit History

### Cycle 1

The independent validator found production use of designer fixtures, fail-open
metadata and URL handling, an enabled service control without a destination,
synthetic public CTA success, inaccessible no-JavaScript FAQ behavior, and a
blank desktop hero media column. Remediation split strict authored generation
from a labeled reference preview, added complete fail-closed normalization,
made service controls truthful, removed the public synthetic state API, used
native disclosures, and added a no-media layout.

### Cycle 2

The validator found that production origin validation still accepted reserved,
local, and IP hosts. Operator inspection also found service-area, reviews, and
FAQ ready-content leakage in `empty`. Remediation restricted production to
credible public DNS hosts and added independent loading/empty branches and
assertions for all six dynamic sections.

### Cycle 3

Final result: **approved with no actionable findings.** The validator directly
rechecked strict/reference isolation, public-origin policy, per-section states,
metadata and JSON-LD, no-JavaScript semantics, action truth, config/router/PIM
regressions, and design-source immutability.
