# D1 — Manifest diff

Reference: `app-templates/customer-portal/design-inbox/manifest.json`
(`wave-17 (modular / customer-portal-design)`)
Production: `app-templates/customer-portal/runtime/manifest.json`
(`runtime-wave9-s6-cms-packaging`)

Generated by a throwaway diff script (not promoted to `scripts/`). It diffs the
four declared dimensions and then reconciles **each manifest against the
attribute literals its own source tree actually emits** — because a manifest
that does not describe its own reality is itself a finding, and that is the
failure mode this wave exists to catch.

Both emission forms are counted: the HTML literal `data-module="x"` and the
JS object-literal form `"data-module": "x"` that `h()` takes.

## Headline

**The runtime manifest is stale by four waves.** Its `version` field still reads
`runtime-wave9-s6-cms-packaging` while the reference is at wave 17. It declares
a strict subset of the design manifest in every dimension — 0 runtime-only
components, 0 runtime-only actions, 0 runtime-only routes — which is not what a
diverged inventory looks like. It is what an inventory looks like when nobody
updated it after waves 14–17 landed.

This is not a presentation finding. It is an **inventory finding**, owned by
this wave per `master.md` §Ownership Zones (`inventory | runtime/manifest.json |
update when the audit proves the real inventory differs`). It is also the direct
cause of one of the four undiagnosed suite failures — see D5.

## 2. Manifest reconciled against its own source

| manifest | declares but source never emits | source emits but manifest never declares |
| --- | --- | --- |
| design-inbox | 12 | 50 |
| runtime | 10 | **101** |

Both manifests under-declare — neither is a complete component census, and the
`components[]` array on either side should be read as a curated list rather than
a generated one. But the asymmetry is the point: the runtime source emits **101**
`data-module` ids its own manifest never names, against 50 on the design side.

The 10 the runtime manifest declares but never emits are identical to the design
side's, minus two, and are all pre-Calm-Harbor:

```
auth-phone, beauty-care-hub, care-hub, health-care-hub, loading-state,
order-detail, otp, proposal-detail, storm-calendar, storm-home
```

These are declared component *concepts* whose ids are not carried as
`data-module` attributes in either tree. Same on both sides, so: not drift.

## 3. `fileInventory` is off by one — measured, not inferred

`runtime/manifest.json` declares:

```json
"fileInventory": { "stylesheets": 7, "srcJavaScript": 95, "runtimeJavaScript": 108 }
```

On disk today: `stylesheets: 7`, `srcJavaScript: 96`, `runtimeJavaScript: 109`.

Traced to commit `84042c5` *feat(customer-portal): read Calm Harbor plans,
purchases and profile from Core*, which added **two** files under
`runtime/src/` (`adapters/core-plans-adapter.js` and
`routes/SpaProductDetailPage.js`, 94 → 96) while bumping `srcJavaScript`
94 → **95**. One short.

Verification:

```bash
git ls-tree -r 84042c5^ --name-only | grep -c '^app-templates/customer-portal/runtime/src/.*\.js$'   # 94
git ls-tree -r HEAD      --name-only | grep -c '^app-templates/customer-portal/runtime/src/.*\.js$'   # 96
```

The `format` string carries the same stale count in prose
(`… 95 src JavaScript modules + 8 non-src runtime JavaScript modules`).

This single off-by-one is what makes `config-behavior-check.mjs` exit non-zero.
See D5 for the full verdict and why fixing the manifest alone does not make that
suite green.

## 5. What D1 does and does not conclude

Concluded:

- The runtime manifest and `runtime/data/scenarios.json` do not describe the
  runtime. Both predate waves 14–17. Two independent measurements agree
  (component census, `fileInventory`), and each maps to one failing suite.
- The stable-hook contract is **not** broken at the census level. `data-route`
  is exact; `data-module`, `data-visual-id` and `data-action` differ by a
  handful of values, each located above.

Not concluded — deliberately deferred, per §D1 "do not judge yet":

- Whether each runtime-only value is an invention or a justified addition. D2.
- Whether the two design-only actions are gaps worth briefing. D2/D6.
- Whether the 55 design-only components are all genuinely present in the
  runtime, component by component. D2 by surface.

## 6. Correction status

**Not corrected in D1.** Per §D1 *Do not*: "Do not 'fix' a manifest to make the
diff clean." The manifest is regenerated as a D6 action only after D2–D4 have
established what the real inventory is, so the update records reality rather
than silencing the diff.
