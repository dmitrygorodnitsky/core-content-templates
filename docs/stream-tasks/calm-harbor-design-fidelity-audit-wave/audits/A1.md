# A1 — Calm Harbor design fidelity audit

Status: `done`. Branch `codex/lab-ui-durable-catalog`.

## What was audited

| slice | scope | instrument |
| --- | --- | --- |
| D1 | `design-inbox/manifest.json` vs `runtime/manifest.json`, plus each manifest reconciled against the attribute literals its own source tree emits | throwaway diff script, not promoted to `scripts/` |
| D2 | every component on the nine priority surfaces — structure, class composition, element order, accepted visual states | three surface agents, side-by-side source comparison, `file:line` on both sides |
| D3 | every stable hook and every user-visible string on those surfaces | 51 recorded greps, all verified against real output, plus two deliberate negatives |

| D6 | punch list, five briefs | — |

The reference was **served and clicked**, not only read: `design-inbox/source.html`
at `http://localhost:8765`, driven through the plan and account surfaces, with its
dev toolbar read directly to establish the accepted route-root state vocabulary.

## Coverage actually achieved

**Audited in full, no sampling:** Appointments, Appointment detail, Booking flow,
Purchases, Purchase detail, Plan, Profile, Account, Orders, Shop, Product detail,
Catalog, Cart, Checkout, plus `CommerceBits`, the six `commerce/**` components,
`StatCard`, and the four shell components. Every component on these surfaces has a
verdict with citations on both sides.

**Sampled, with the rule stated:** the 16 non-priority routes in D4 §1 — for each,
the route root and its `routeStateBody` gate were read and the declared set compared
to the gate's `states` array. Two gaps surfaced (`LT-01`, `LT-02`).

**Measured with pixels:** 16 pairs at 390/768/1180/1440 (wave16, Chrome 150).

**Inherited, not re-measured:** 28 pairs (wave15 12, wave17 16). Both suites render
reference and implementation in the same run with the same browser, so their
comparison is internally valid whichever browser produced it. Re-running a green
suite was out of scope.

**Not measured at any width:** the three wave14 surfaces (orders, services, products
under the staging export). That suite is blocked by a harness fault whose fix lives
in `scripts/`, outside this wave's ownership.

**118 findings.** `invention` 22 · `gap` 12 · `drift` 34 · `decision` 33 ·
`design-gap` 15 · inventory 2.

## What was corrected

**Nothing.** No file under `runtime/` or `design-inbox/` was modified; `git status`
was clean before and after every measurement. Three reasons, recorded because "we
found a lot and fixed none" needs one:

1. **The severe findings are not presentation.** All eleven HIGH findings originate
   in `runtime/src/adapters/**`, `runtime/src/actions.js` or `runtime/src/state.js`
   — outside the `production presentation` zone (`routes/**`, `components/**`,
   `styles/**`) that `master.md` §Ownership Zones lets this wave correct.
2. **The clearest deletable "inventions" are load-bearing.** `A-24`
   (`data-visual-id="support-dismiss"`) has no design counterpart and is exactly the
   shape of a removable invention — but
   `calm-harbor-customer-portal-manual-check.mjs:189` clicks it. `SG-01` is the same
   trap at larger scale: the orders route root's raw error codes read as drift on a
   contract attribute and are asserted deliberately at `:198` as the fail-closed
   signal for a foreign Order. Both would have been "corrected" into broken checks by
   an audit that trusted the census over the tests.
3. **Some runtime files *are* the accepted source.** `SpaCartPage.js` and
   `CommerceBits.js` are byte-identical to `design-inbox`. `AC-C03`'s unreachable
   `unavailable` treatment lives in that identical code. Changing it would mean
   diverging from the reference this wave exists to measure against.

Because no runtime file was touched, the release compile was not mandatory. It was
run anyway as a tree health check:
`node app-templates/customer-portal/scripts/build-calm-harbor-target-runtime.mjs`
→ `build-calm-harbor-target-runtime ok`, idempotent, `git status` clean after.

## Corrections to the record

Three places where the audit contradicts something already written down. Each is
evidenced, not asserted.

**1. `S4.md` §3 — "Both treatments are accepted design" is wrong on one half.**
The *gate* on `SpaPlanPage`'s unavailable block is a recorded decision and reads as
intended. The *block itself* has zero design counterpart — 0 matches across 315
`design-inbox/` files, a different `data-visual-id`, glyph and copy from the accepted
`UnavailableState`. Found independently by D1's hook census and by the account agent.
`master.md` §Core Rules 4 protects recorded decisions, not incidental prose about
provenance.

**2. `master.md` Known Starting Point 2 is broader than reality.** It names
`RETURN_REQUESTED` *and* `RETURNED`. The first already has an accepted treatment
(`design-inbox/.../SpaPurchaseDetailPage.js:28`, and `return-accepted-for-review` is
in the declared grammar). Only a completed return lacks one. The brief asks for that
alone; briefing both would have asked the designer to redo shipped work.

**3. `slices.md:91`'s example grep does not hit.**
`rg -n 'data-visual-id="plan-card"' …` returns nothing — these sources build
attributes as JS object literals, so the working form is
`rg -n '"data-visual-id": "plan-card"'`. Found independently by D1 and by two of the
three surface agents. Every grep recorded in this wave uses the source form.

A fourth, against this package's own method, is recorded as `RS-01`: D5 asks for a
comparison against `design-inbox/previews/` at four widths, but 170 of the 217 stored
previews are a fixed 908×540 frame. The width in the filename names the scenario, not
the raster width, so that pixel comparison cannot be made. The same-run re-render the
per-wave suites already use is the correct instrument.

## Judgment calls

Merged from the three surface agents, plus the operator's own.

**O-1 — the surface agents were forbidden from editing `runtime/`.** `master.md`
permits removing a clear invention during D2. Running three agents concurrently with
deletion rights over shared presentation would have put the "never invent, only
delete inventions" rule in three hands at once, and the mandatory release compile in
none. Agents reported; deletion stayed with the operator. In the event this was
load-bearing — see `A-24` and `SG-01` above, both of which look deletable and are
not.

**O-2 — `SG-01` was nearly filed as a contract break, and was not.** The orders route
root carrying `orders-request-failed` reads as textbook drift, and three sibling
modules in the same file show the "correct" mapping. Checking `scripts/` before
filing found `calm-harbor-customer-portal-manual-check.mjs:198` asserting it
deliberately. Filed as `design-gap` — the grammar never described a real, tested,
security-motivated behaviour. This is exactly the failure mode `master.md` §Core
Rules 4 exists to prevent, and it was one grep away from happening.

**O-3 — wave16's reference PNGs were restored after capture.** The suite rewrites 37
files into another wave's evidence directory on every run. The report was captured,
two artifacts were copied into this package, and `git restore` returned the directory
to the baselines the previous browser produced.

**J-1 (appointments) — findings whose root cause sits outside the owned files were
recorded, not dropped.** `A-06`, `A-07`, `A-21`, `A-26` decide what the appointments
surfaces render. Dropping them would have produced a clean but false verdict. Each is
labelled with its owner.

**J-2 (appointments) — "behaviour-preserving in fixture mode" was proved, not
assumed**, by checking the fixtures and the writer count rather than eyeballing
diffs.

**J-3 (appointments) — one hazard is recorded as latent, not as a live defect.**
`runtime/src/actions.js:503-505` adds `&& state.spaBooking === "open"` to
`spaFlowCapable()`, which the design does not have, so a `booking.open` dispatched
while booking is closed would fall through to the legacy drawer whose review claims
*"Your time is held for 10 minutes while you review"* — copy `S1.md` §7.3 forbids and
the settled no-holds decision contradicts. All five Spa `booking.open` call sites
were traced and every one is gated, so it could not be demonstrated reachable. Filed
latent rather than as a defect.

**J-4 / J-5 (appointments) — the known starting points were confirmed rather than
rediscovered**, and nothing outside the two findings files was touched.

**1 (account) — `AC-C03` is classified by effect, not by cause.** The design
describes the treatment and the runtime does not render it: that is `gap`.
Classifying by cause would have routed it to "remove", which would be wrong.

**3 (account) — `AC-C10` and `AC-C23b` are `invention` but marked do-not-delete.**
`master.md` §Core Rules 3 permits removal "only when removal restores the accepted
state". Neither removal does — both would leave a silently missing section. They must
be *replaced* via brief 3, not deleted.

**5 (account) — latent findings are reported at full detail with severity discounted
for reachability**, rather than dropped. `SpaOrdersPage` ships in every build; a
one-attribute capability change makes `AC-C29`–`C33` live at once.

**2 (commerce) — `C-12` is `drift` against the design *source*, and the runtime is
the compliant side.** The design *manifest* declares `states: ["ready","unavailable"]`
with "data-state on the container"; the design *source* omits it. `ARCHITECTURE.md`
§Accepted Design Metadata Reconciliation gives the manifest precedence.
Accept-with-reason, not a runtime fix.

**3 (commerce) — the two large line-count deltas were proved mechanically.** Rather
than assert "the runtime is more compact", both sides were reduced to element
signatures and attribute-value sets: product detail is 76 elements = 76 elements with
zero differences; shop is 53→51, explained by one refactor and one addition. The −92
and −45 are comments and collapsed calls, **not lost presentation**. This is the
finding that prevented two unnecessary briefs.

**4 (commerce) — fixture-mode arithmetic is not filed as a defect.** A fixture
standing in for a server response may legitimately produce the figures the server
would. `C-01`/`C-03` are scoped strictly to live / `current-api` mode, where the same
arithmetic runs in production command code and is persisted to Core.

**5 (commerce) — the honesty rule was applied against the accepted source too.**
`CartRow`'s client-side line total is recorded against both sides rather than
exempted because the design does it as well.

## What could not be checked

- **No DOM was rendered for D2/D3.** Every component and copy claim is source-level.
  The one exception is the orders fail-closed path in D4, which was driven live.
- **`design-inbox/previews/` was not pixel-compared** — see `RS-01`. No runtime
  layout is claimed verified against a stored preview.
- **wave15 and wave17 were not re-run under Chrome 150.** Their pass is inherited.
- **wave14's three surfaces have no pixel measurement from this wave.**
- **`[data-purchase-ref^="order-core-"]` has still never executed** — the source-side
  contract is verified on both ends; the browser assertion is not.
- **Templated and mode-gated hooks are source-verified, not DOM-verified** —
  `"account-entry-" + e.key` and the three hooks that vanish under live config need a
  rendered check.
- **`seo.css` (107 diff lines)** was seen and deliberately not analysed; no Calm
  Harbor surface uses it.
- **`PricingPage.js`, `ProductsPage.js`, `CheckoutPage.js`, `ServicesPage.js`** were
  read only to confirm changed props are exercised. They are not audited.
