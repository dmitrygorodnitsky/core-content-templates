Это уточнение к DEPENDENCIES-AND-TRANSFER.md. Никаких серверных изменений. Предыдущая оценка блокеров была избыточно строгой: она учитывала всё дерево, включая выключенные блоки и неиспользуемые параметры.

## Домен — решение принято

После переноса backend переключит servicewand.com на новый prod. Конечный публичный адрес остаётся servicewand.com. Массовую замену домена не делаем. До переключения абсолютные ссылки могут обращаться к старому серверу; особенно важно не выполнять тестовую отправку форм на старый backend. Проверка временного prod URL и окончательного публичного адреса — разные этапы.

## CSS/JS

Шесть отсутствующих CSS/JS подключены корнями USECASES_JTE, TEMPLATE-CORPORATE_LANDING и VERTICAL_LANDING_JTE. На соответствующих зарегистрированных страницах `/use-cases.html`, `/documentation/overview.html`, `/industries/field-service/landscaping-software` в включённых блоках нет вызовов DynamicForm.

Поэтому 404 не доказывает, что именно формы этих страниц сейчас не работают. Это кандидаты на старые подключения. Перед удалением из пакета нужно проверить rendered HTML и остальные динамические потребители CSS/JS; пока подключения не удалены и совместимость подмены не заявляется.

Исправная dynamic-form.js есть на источнике и обслуживает корпоративный landing. В репозитории также есть js/dynamic-form.js и test/css/dynamic-form.css, но локальный JS отличается от серверного (72 832 против 152 557 UTF-8 байт; контрольные суммы различаются). Брать локальную версию вместо серверной автоматически нельзя.

Две дополнительные stream-ссылки с 404 принадлежат CORPORATE_WEBSITE_TEMPLATE, который не включён в предложенный основной пакет.

## Изображения

Все три спорные ссылки дают HTTP 200, Content-Type image/gif, но **0 байт**. Оригиналы по этим URL недоступны.

- `3363653c…` и `1ebd019f…` — старые фоны Request Demo. Реальное использование найдено в CSS/предзагрузке CORPORATE_WEBSITE_REQUEST_DEMO_SECTION из исключённого старого дерева. В PRIVACY_POLICY, TERMS_AND_CONDITIONS и ещё двух блоках это оставшиеся параметры REQUEST_DEMO_BG_1/2: в собственных head/html/css/javascript они не используются. Считать их обязательными изображениями текущего сайта оснований нет; удаление параметров требует отдельной аккуратной правки пакета.
- `bbc735d9…` — иллюстрация в содержимом поста. В медиатеке SERVICEWAND найден `Service Wand and the Argument for One Operational System1.png` под ID `575ce6ba-4770-4769-bdc9-c14e66ac18a3`. Имя совпадает с исходной ссылкой. Это конкретный кандидат на восстановление, но потерянный оригинал недоступен для сравнения хешей. Следующий шаг — посмотреть изображение и проверить соответствие статье; в правилах переноса ссылка должна разрешаться через запись медиа, а не жёстко заданный prod ID.

## Куда направлены включённые формы

Ниже результат параметров блоков с учётом overrides страниц; отправка формы не выполнялась.

| Страница | Тип формы | Организация |
|---|---|---|
| /request-demo.html | GENERAL_PARTNERS_FORM | SERVICEWAND |
| /partner.html | GENERAL_PARTNERS_FORM | PNI |
| /index.html | GENERAL_PARTNERS_FORM | PNI |
| /snow-removal-request-demo.html | SNOW_REMOVAL_REQUEST_DEMO | SERVICEWAND |
| /field-service-early-access.html | FIELD_SERVICE_EARLY_ACCESS | PNI |

Отдельная неожиданность: `/request-demo.html` сейчас использует GENERAL_PARTNERS_FORM, а не REQUEST_DEMO_FORM_TYPE. Это актуальная настройка источника, её нельзя незаметно «исправить» при переносе.

Предложение для команды: все маркетинговые заявки сайта направлять в SERVICEWAND. Но смена PNI на SERVICEWAND — изменение бизнес-настройки, а не техническое сопоставление ID. До решения сохраняем исходное распределение, разрешая целевые организации по кодам. Тип формы на Request Demo тоже сохраняем до явного решения.

## Что осталось решить

1. Согласовать очистку старых CSS/JS-подключений после проверки rendered HTML вместо поиска заведомо ненужных версий.
2. Проверить найденную иллюстрацию и восстановить одну ссылку блога.
3. Подтвердить назначение всех маркетинговых форм в SERVICEWAND либо сохранить текущее PNI/SERVICEWAND.
4. Уточнить, намеренно ли Request Demo использует GENERAL_PARTNERS_FORM.

Домен больше не является открытым вопросом. Два фоновых изображения не блокируют основной пакет. Отсутствующие CSS/JS остаются предметом проверки перед очисткой, а не доказанным функциональным сбоем трёх страниц.
